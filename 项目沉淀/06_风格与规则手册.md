# 风格与规则手册

本项目审片过程中，用户逐条提出、确认过的规则。下个同类项目开工时，把这份文件作为约束交给所有智能体。引号里是用户原话。

## 一、总原则

1. **结构和节奏优先于细节**：“我们的制作成本和制作周期都不允许非常的精细，所以不必在细节上较真，更重要的视频的结构和节奏。”
2. **可以简约，不能简陋**：“你可以简约，但不能简陋。”表达形式粗糙的页面要推翻重做。
3. **普通人一眼能看懂**：讲专业概念（例如日照）时，用对照组、阴影这类直观方式。“你这个太专业了，能让普通人一眼看明白。”
4. **三维只讲逻辑，品质交给实景**：模型精细但不写实，不追求豪华感。“不要强调场景里的豪华感，这样会和项目实际实景展示冲突。”
5. **导演负责制**：主控 AI 是导演和编剧，把控篇幅和节奏；能外包的写任务书外包，做好约束和验收。

## 二、画面风格

- **全片自绘、统一风格**：
  - 效果图、实景图只作参考（立面特征、位置关系），不直接放进成片：“我最早给你效果的目的其实是让你参考他们的立面效果、位置关系等，并不是让你直接放到成片里。”
  - 看完成片后，再决定是否加写实图。
- **场景统一**：区域、规划、户型三类场景的表现方式要一致，不要“拼接感”。
- **户型用立体模型**：剖切沙盘，有立体感；不做户内穿梭；户型图上下垂直摆放，不做角度偏移。
- **户型部分不用 AI 生成**：“他们有明确的交付标准，这块不需要发挥太多创意。”
- **配色**：底色纸色 `#F3F0EA`；赤陶 `#C25A2C` 只给 2 号楼、视线和标题条；地标（五大馆等）`#E6D2AA` 是第二级重点；夜景为蓝紫色调。完整色板见 `视频/动画工程/src/v2/theme.tsx`。
- **字体**：标题宋体（Songti SC），正文和标注用苹方（PingFang SC）。
- **版式**：
  - 不要像 PPT，标题位置可以随镜头变化。
  - 同一张底图不断“长”出信息，而不是一直切画面。
- **首尾呼应**：片头、片尾都是纯黑底，文字浮现、淡出，用同一张标题卡版式。
- **图例和装饰**：避免太“巧”、太“愣”的几何图形（例如圆形图例被否）。
- **地标**：上海大剧院等参考线稿要“一眼能认出”，不要粗糙线条。
- **模型精度**：“精细但不写实”。
  - 住宅立面：白楼板 + 通长深色玻璃 + 香槟金转角线 + 冠顶金色格栅，四面统一。
  - 写字楼立面：竖梃 + 层间横带。
  - 基坑地块：保持不起眼的扁平方块，不要做成建筑。

## 三、标注与版式规则

- **标注框统一规则**：
  - 框顶距画面顶 150px，水平居中对准目标，左右至少留 96px；
  - 从框底竖直引线到目标点；
  - 标注随画面缩放跟随目标。
- 左上留给章节标题，右上留给示意小图，下方留给字幕。
- 楼层、楼栋数据必须来源于真实数据（总平面标注），不要编。
- 不要加不准确的标签（例如“第一批次、第二批次”）。
- 画面底部的来源说明小字：成片最终全部去掉（v11）。署名在发布文字里补，见 [合规](07_合规与发布前检查.md)。

## 四、字幕

- 数字一律用阿拉伯数字：355㎡、22.8米、104户、300平以上。配音照常念中文。
- 同一屏字幕不出现重复词（例如两次“名片”）。
- 字幕颜色和位置要考虑底图，不能在复杂背景上用黑字。
- 字幕必须和画面一致；开工前出一张“字幕与画面核对表”给用户人工核对（见 `视频/HR-VIDEO-005_字幕与画面核对表.xlsx`）。
- 前后编号要衔接（例如开头列了“一二三四五”，后面展开时要有过渡，而不是从头开始）。

## 五、用词与文案

| 不用 | 改用 / 说明 |
|---|---|
| 平面 | 户型 / 空间（客户不熟悉“平面”） |
| 勇气 | 耐心（长期主义） |
| 麦田 | 田地 |
| 龙城的风景 | 太原的风景 |
| 算一笔阳光账 | 太 AI 腔，不用 |
| 精打细算 | 数字游戏（“拿电梯前室的面积玩数字游戏”） |
| 第一步、第二步 | 太死板，不用 |
| 夏邦杰全名 | 直接说“夏邦杰” |
| 侧身不是回避正南 | 这句不好，删 |
| 侧身（全片近 10 次） | 控制次数，片名和结尾保留作呼应 |
| 长风商务区就在脚下（低层画面） | 近在咫尺 |

- 文章标题要有网感，“让每个看到的人想点看，别太冷冰冰盛气凌人”。
- 绝对化表述（天花板、楼王）甲方能接受风险，可以用。发布前过一遍广告法，见合规文档。
- 南向两间卧室不分主次，可以是南向双主卧。

## 六、配音与节奏

- 重点内容不能一带而过：两栋楼转身后能看到的景色是全片重点，要逐个展开。
- 用户本人录音；录音后音频不再调整，画面可以继续优化。
- 局部修改要说明时长变化；需要时压缩，“尽量别延长太多”。
- 章节过渡卡（一 位置、二 楼栋……）保留。用户一度想去掉，后来决定保留。

## 七、协作与交付

- 局部修改只出对应片段（替换片段），不重出整片，除非用户要求。
- 修改完一段单独确认；确认后存档，最终成片只用确认过的版本。
- 外包智能体：
  - 任务书要写清坐标、色板、接口、自检标准；
  - 验收用成片真实机位实测；
  - 不通过的包只返工那一个包。
- 用户睡觉或离开时可以授权“过程中不要问我”，按已确认的意见一次做完。
- 大文件（录音、视频）用“文件”方式传，不用微信“视频”（会被压缩）。
- 磁盘空间由用户自己清理；删除用户的文件之前必须先问。
