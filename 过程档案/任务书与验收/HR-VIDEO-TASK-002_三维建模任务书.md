# 《一栋楼，为太原转了个身》三维建模任务书

## 0. 先读这一段

这是一条约2分50秒的建筑科普动画。画面全部是浅色体块的白模风格，靠镜头运动和光影出效果，**不需要精细模型，也不需要贴图**。

**你的任务是准备“场景数据”和少量“体块模型”。** 镜头、灯光、动画、材质渐变都由导演在合成阶段用 Three.js 统一做。所以你交付的东西必须**干净、命名统一、坐标统一**，比好看更重要。

开始前请读完这四个文件：
1. 分镜脚本：`视频/脚本/HR-VIDEO-001_一栋楼为太原转了个身_分镜脚本.md`。知道每样东西在哪个镜头出现、要做什么动作。
2. 制作计划：`视频/HR-VIDEO-PLAN-001_制作计划.md`。
3. 两条参考视频：`视频/参考视频/`。只看画面风格，不需要复刻。
4. 素材收集结果：由两位素材 Agent 同时在收集，分别写在：
   - `视频/素材/汇报.md`、`视频/素材/登记表.csv`：地理数据、地标参考等（HR-VIDEO-TASK-001）；
   - `视频/素材/汇报_补充.md`、`视频/素材/登记表_补充.csv`：高程数据、材质与光照（HR-VIDEO-TASK-003）。

**开工顺序：** 先做4.1户内模型，它完全不依赖素材，现在就可以开始。4.2地形等 `视频/素材/10_高程数据/` 交付后再做；4.3到4.5等 `视频/素材/01_地理数据/` 和 `02_地标参考/` 交付后再做。等待期间不要自己去下载这些数据，也不要往 `视频/素材/` 里写任何东西。

**原则：宁可简单，不要错。** 数据里没有的东西（例如地图上没有谐园的边界），不要自己编造，在汇报里写出来，由导演决定。

## 1. 工作边界

**要做：** 第4节列出的六项交付，全部放在 `视频/模型/` 下。

**不要做：**
- 不做镜头、灯光、动画、渲染成片。
- 不加贴图，不做写实材质。材质只留“插槽名”（见第3节）。
- 不改动资料库里已有的任何文件。`立体户型模型/`、`项目资料/`、`视频/素材/` 只读。
- 不登录、不付费。需要安装的工具只用第2节列出的开源库。
- 不要为了“好看”改动真实位置、朝向和尺寸。

## 2. 工具

- **Python 3**，用 pip 安装：`shapely`、`pyproj`、`numpy`、`pillow`、`matplotlib`、`trimesh`、`mapbox-earcut`。
- **校验 GLB**：`npx gltf-validator <文件>`；统计面数：`npx @gltf-transform/cli inspect <文件>`。
- 本机没有 Blender，不要依赖它。
- 所有处理过程写成脚本，放在 `视频/模型/源文件/`，保证导演能一条命令重跑。

## 3. 统一约定（所有交付都必须遵守）

### 3.1 坐标

- **单位：** 米。
- **原点：** 山西大剧院建筑轮廓的形心。把它的经纬度写进 `视频/模型/scene_meta.json`。
- **坐标轴：** 和 Three.js 一致：**+X 向东，+Y 向上，−Z 向北**（也就是 +Z 向南）。
- **投影：** 用 pyproj 把经纬度转换到 UTM 49N（EPSG:32649），再减去原点。所有图层都用同一套换算。

### 3.2 高度层

不同图层放在不同高度，避免闪烁：

| 图层 | Y 值 |
| --- | --- |
| 水面 | −0.6 |
| 地面、地形基准 | 0 |
| 公园、绿地 | 0.05 |
| 道路 | 0.08 |
| 文化岛平台 | 抬高后的平台高度，见4.3 |

### 3.3 材质插槽名

GLB 里只用纯色材质，名字必须是下面几个之一，导演会按名字替换成真正的材质：

`white_model`、`white_model_dark`、`glass`、`water`、`green`、`road`、`wood_floor`、`stone_floor`、`fabric`、`accent`

### 3.4 命名

- 文件名、节点名一律用英文小写加下划线，例如 `venue_grand_theatre`、`ruifu_b02`。
- 每个可以单独做动画的东西必须是**独立节点**，并且**节点原点在它的底面中心**，方便做升起、旋转等动作。

## 4. 交付清单

按顺序做。每完成一项，先做第5节的自查，再做下一项。

### 4.1 户内模型 `视频/模型/unit_b02.glb`（不依赖素材，最先做）

**用途：** 镜18到镜23：穿窗进屋、悬浮沙盘、沿路线穿行、空间逐个长出材质。

**数据来源：** `立体户型模型/model-data.json`。这是1号楼的平面，**2号楼是它的东西镜像**：x 换成 22.8 − x，y 不变。可以参考已有的构建脚本 `视频/anatomy/ruifu-2/build.mjs`，它已经处理过镜像、凹形墙柱拆分、隔墙裁切、家具避墙，逻辑可以照搬。

**要求：**
1. **墙：** 实墙柱和隔墙拉伸到**2.9米**整层高度（这是动画用的假设高度，不是层高数据），材质 `white_model`。剖切动画由导演在着色器里做，你不用切。
2. **窗：** 沿外墙没有墙柱的段落放窗：窗台高0.6米，其上到2.9米是玻璃面，材质 `glass`；每隔约1.2米放一根细竖梃，材质 `white_model`。
3. **地面：** **每个房间一块独立的地面**，节点名用 `floor_<房间id>`，例如 `floor_living`。材质：客厅、餐厅、茶区、卧室用 `wood_floor`，卫生间、厨房、家政间用 `stone_floor`。导演要逐个房间做“长出材质”的动画，所以必须分开。
4. **家具：** 用简单体块（沙发带靠背和扶手，床带床头板，餐桌是圆柱），尺寸和朝向取自数据。每件家具一个节点，节点名 `furn_<家具id>`，并归到所在房间的父节点 `room_<房间id>` 下。沙发、床的布面用 `fabric`，桌柜用 `white_model`。
5. **路线锚点：** 另外输出 `视频/模型/unit_b02_points.json`，写出这些点在本户坐标里的位置（米，以户型左下角为原点，同时给出转换到整栋楼坐标的说明）：南窗客厅点、餐厅圆桌中心、茶区北窗点、玄关点、主卧中心、衣帽间中心、主卫中心。这些是纵线、横线的节点。
6. **面数：** 整个户内不超过15万个三角面。

### 4.2 地形 `视频/模型/terrain/`

**用途：** 镜1的暗色地形和倒带，镜4到镜10的造岛，镜24的拉出。

**数据来源：** `视频/素材/10_高程数据/`（由 HR-VIDEO-TASK-003 交付，外框和瓦片范围见 `10_高程数据/tiles.json`）。

**要求：**
1. 把瓦片拼成一张覆盖素材外框的高度图，输出16位灰度 PNG：`terrain/height.png`，2048×2048。
2. 输出 `terrain/terrain_meta.json`：四至坐标（米，本场景坐标）、最低和最高海拔、每像素多少米。
3. 不要做成网格模型，导演会在 Three.js 里用这张高度图生成地形。
4. 输出一张预览图 `terrain/preview.png`：用 matplotlib 画出高度图，叠上汾河轮廓，确认两者对得上。

### 4.3 城市与文化岛数据 `视频/模型/city/`

**用途：** 镜1倒带（楼群缩回地面）、镜4规划线落地、镜6到镜10造岛和城市生长、镜11到镜15瑞府、镜23窗外。

**数据来源：** `视频/素材/01_地理数据/`。

**输出 GeoJSON 风格的 JSON 文件，坐标是本场景的米制坐标（x 向东，z 向南），不是经纬度：**

| 文件 | 内容 | 要求 |
| --- | --- | --- |
| `buildings.json` | 所有建筑轮廓 | 每栋：`id`、`polygon`、`height`、`district`。轮廓按1米精度简化；去掉面积小于30平方米的；`height` 取值优先用 `height` 标签，其次用层数乘以3.2米，都没有就按第4.3.1条估算，并加一个字段 `height_estimated: true` |
| `water.json` | 汾河水面、文化岛内河 | 分成两个要素：`fen_river`、`inner_river`。如果地图里没有内河，写进汇报，不要自己画 |
| `parks.json` | 和园、谐园、汾河公园等 | 用地图上的名字；找不到名字的公园标 `unnamed` |
| `roads.json` | 主要道路中心线 | 只保留 primary、secondary、tertiary、trunk 四类；每条带 `class` 和建议宽度（米） |
| `island.json` | 文化岛平台外轮廓 | 取内河内圈。没有内河数据时，按五大馆外包轮廓外扩40米，并标 `estimated: true` |
| `venues.json` | 五大馆各自的轮廓 | 从 `buildings.json` 中按名字找出来，给出 `name`、`polygon`、`height` |

**4.3.1 高度估算规则（数据里没有高度时）：**
- 长风商务区范围内（`district = changfeng`）：面积大于2000平方米的取80米，其余取45米。
- 其他住宅区：取54米。
- 其余：取15米。
- `district` 只分三类：`changfeng`（长风商务区，大致是汾河西岸、文化岛周边2公里内）、`ruifu`（瑞府地块）、`other`。分区边界写进汇报，画一张示意图。

**4.3.2 预览：** 输出 `city/preview.png`：俯视图，水面蓝、公园绿、道路灰、建筑按 `district` 着三种颜色，标出原点、五大馆名字和瑞府地块。

### 4.4 五大馆体块 `视频/模型/venues/`

**用途：** 镜8“五馆拔地而起”、镜14视线扫到五大馆、镜23窗外。

**数据来源：** `venues.json` 的轮廓，加上 `视频/素材/02_地标参考/` 里的照片。

**要求：**
1. 每座馆一个 GLB：`venue_grand_theatre.glb`、`venue_library.glb`、`venue_art_museum.glb`、`venue_science_museum.glb`、`venue_museum.glb`。名称若与官方不同，在汇报里写明对应关系。
2. **只做能认出来的大轮廓。** 用拉伸、斜切、圆柱、球面这类简单形体，把照片里最有特点的一两处做出来，例如屋顶的弧线、体块的错落。每座不超过5000个三角面。
3. 轮廓位置和占地以地图为准；高度以登记表里的资料为准，查不到就按照片目测估计，在汇报里写明是估计值。
4. 材质只用 `white_model` 和 `glass`。
5. 节点原点在底面中心，Y=0 是平台面。
6. 每座馆输出一张预览：`venues/<名字>_preview.png`，用 matplotlib 画出45°俯视的线框或轮廓，旁边放一张参考照片，方便导演对照。

### 4.5 瑞府楼栋 `视频/模型/ruifu/`

**用途：** 镜11到镜18：总平面落下、楼体立起、两栋转身、暗场亮相、窗亮起。

**数据来源：** 甲方总平面（如果素材里有）；没有就用 `buildings.json` 里 `district = ruifu` 的轮廓，以及鸟瞰图 `配图参考/03_1号楼与和园汾河_鸟瞰示意.jpg` 和楼号对照。

**要求：**
1. 每栋楼一个独立节点 `ruifu_b01`、`ruifu_b02`……，T1到T3等非住宅楼用 `ruifu_t01` 这样的编号。全部放进一个 `ruifu.glb`。
2. 每栋做成简单的长方体或者轮廓拉伸，高度按层数乘以3米估算（不知道层数就统一取54米），立面用横向分隔线表示楼层，材质 `white_model`。
3. **1号楼、2号楼要单独处理：**
   - 测出它们在地图（或总平面）上的实际朝向角度，写进 `ruifu/ruifu_meta.json`，字段 `b01_angle_deg`、`b02_angle_deg`，以正北为0、顺时针为正。
   - 节点自身先按“正南正北”放置，再把实际角度写成节点的旋转。导演会从0度动画旋转到实际角度。
   - 2号楼立面上按窗的位置做出可以单独点亮的窗面：每层南立面一条窗带，材质 `glass`，节点名 `b02_win_<层号>`。层数不知道就按18层做，写进汇报。
4. 输出 `ruifu/preview.png`：总平面俯视图，标出楼号、1号楼和2号楼的朝向角度。

## 6. 复核节点

导演会在三个节点复核，每个节点做完后先停下来，在汇报里写“等待复核：节点N”，等确认后再继续：

1. **节点1：** 4.1户内模型和它的预览。
