## 3. F 户型室内（最优先）

### 3.1 问题

**问题 1：坐标混用（硬伤）。** 原任务书 7.F 要求“写进 GLB 时 z = y − 17.9”（y 是平面“距北边”的米数）。交付的 `unit_b02_detail.glb` 里两套坐标混用：

| 节点 | 现在的 z 范围 | 判断 |
|---|---|---|
| `floor_*`、`skirt_*` | 0 – 17.9 | 用了平面 y，错 |
| `wall_solid_*` | −9.84 – 17.67 | 两套混用，错 |
| `core` | −11.52 – 9.99 | 两套混用，错 |
| `window_*` | 全在原点附近（x −1.2 – 1.2，z ≈ 0） | 没放到窗洞，错 |
| `wall_partition_*`、`door_*`、`lift_*` | 负值 | 对 |
| `unit_furnish.glb` 全部 | 负值 | 对 |

后果：接进片子后，地面、踢脚和部分墙整体落在户型南边 17.9m 外，窗户全堆在西北角。片中“讲到哪个房间、哪个房间地面变色”的效果全部失效。

### 3.2 怎么改

1. `unit_b02_detail.glb` 所有节点统一用 **z = y − 17.9**。查清 `build_F_unit.py` 里哪几处直接写了 y，全部改掉。
2. 窗户：
   - 按旧 `unit_b02.glb` 的窗洞位置和朝向，把每组 `window_*_glass / _mullion / _sill` 放到位；
   - 位置直接烘进顶点，或者写在节点 translation/rotation 上，二选一，全包统一。
3. 其余保持不变：
   - 墙高 2.9m（剖切由动画端做）；
   - 电梯只做门套、不做门扇；
   - 节点命名不变，`floor_<id>` 仍是每个房间一个独立网格；
   - 三处官方图修正保留：打通多功能区、补全东南卧室过道墙、家政间东墙三段式。

### 3.3 新增自检（结果写进 `F_unit/meta.json` 和 `进度.md`）

## 4. E 文化岛平台

### 4.1 问题

`island_paving` 是一整块覆盖全岛的铺装，顶面约 40 万㎡。片中岛顶本来由底图画着草坪、园路和广场，现在全被盖住：
- 白天整个岛是一片米色；
- 夜景是一块黑，原来亮着的园路图案没了。

### 4.2 怎么改

1. **删掉覆盖全岛的顶面。** 岛顶的底色交给动画端底图。
2. **顶面只做“贴在底图上”的点缀**，而且只放在底图上本来是铺装或广场的地方。
   - 底图：`动画工程/public/v2/ground_day.png`，只用 Python 读像素。
   - 坐标换算：范围在 `动画工程/public/v2/trees.json` 的 `bounds` 字段，格式 `[x0, z0, 边长]`。
     - 图片左上角是 (x0, z0)，向右 x 增大，向下 z 增大；
     - 每像素 = 边长 / 图宽。
   - 判定：先用像素颜色分出“草坪”（偏绿）和“铺装/广场/园路”（偏浅灰、米色），把分类阈值写进决定记录。
   - 铺装分格线（`planter` 细条，高出顶面 0.06m）只做在铺装区里；
   - 草坪区留空，不放任何面。
3. **这些保留不动**：
   - 边缘石材立面和竖缝；
   - 顶边 1.1m 玻璃栏板；
   - 两处大台阶；
   - 两处车行洞口；
   - 大剧院到图书馆的 8m 主步道和两侧树池；
   - 庭院灯、座椅实例。
4. **平台高 6.0m 正确**，和片中一致，不改。
5. 灯具、座椅、树池如果落在草坪区，挪到最近的铺装区；挪不了的删掉。

### 4.3 新增自检

1. 顶面（y ≥ 5.9 的朝上三角面）总面积 ≤ 岛面积的 35%。分材质列出面积。
2. 顶面网格落在“底图草坪区”里的面积 ≤ 顶面总面积的 5%。
3. 实例（灯、座椅）落在草坪区的数量为 0。

## 5. B 小区园林

### 5.1 问题

1. **绿篱几乎没做。**
   - `site_hedges` 的顶面合计只有约 29㎡，折合不到 40m 长。
   - 任务书要求铺装和草坪交界处做连续绿篱带；你的决定记录第 13 条也写了“沿交界线做 0.8m 连续带”，但产物里没有。
2. **树种是平均分配的。** `trees_site.json` 的 1,324 棵树：
   - 0 号 296、1 号 274、2 号 264、3 号 234、4 号 256。
   - 一大半是橙色色叶树（4 号）、蓝绿锥形常绿（1 号）和水岸垂柳（3 号）。
   - 片中整个小区因此显得发白、发花，和片中、和园的绿色调都不一致。
3. **地面偏浅。** 浅色铺装、园路、植草砖读得比草坪多，小区绿意明显比片中现状少。

### 5.2 怎么改

**1. 绿篱**
- 沿“铺装 ∩ 草坪”交界线全长，在草坪一侧做连续带：宽 0.8m、高 0.75m，`hedge`，用折线挤出，不要一个个球。
- 入口、园路开口、消防道交叉处断开 3m。
- 碰到树池、灯位就让开，不要穿插。

**2. 树种比例**（和园原型编号：0 圆冠落叶乔木、1 锥形常绿、2 灌木丛、3 水岸垂柳、4 色叶小乔木）
- 0 号 ≥ 65%；
- 1 号 ≤ 10%：只放在楼栋入口两侧对植，以及围墙内侧；
- 2 号 ≤ 15%：作林下层，贴着乔木或绿篱；
- 3 号：只放在景观水面 6m 以内；
- 4 号 ≤ 5%：只放在入口广场和主要铺装节点，作点缀。
- 树的**位置不变**，只重新分配树种；尺寸按树种合理调整，冠径和高度写进决定记录。

**3. 地面分类复核**
- 用 `动画工程/public/v2/site_day.png` 复核草坪、铺装、园路的分类：
  - 只用 Python 读像素；
  - 范围在 `site_meta.json` 的 `bounds`，0.4 米/像素。
- 片中现状是草坪的地方，必须是 `lawn`；
- `grass_paver` 只用在消防车道；
- 铺装和园路不外扩。

### 5.3 新增自检

1. 绿篱总长度，以及占“铺装 ∩ 草坪”交界线全长的比例：应 ≥ 70%。
2. 树种分布表，满足 5.2 第 2 条的比例；3 号树到最近水面的距离都 ≤ 6m。
3. 地面各类面积占比，和 `site_day.png` 同类像素占比对照：每类偏差 ≤ 5 个百分点。
