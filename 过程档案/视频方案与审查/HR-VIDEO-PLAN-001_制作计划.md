# 《一栋楼，为太原转了个身》制作计划

## 1. 定位与原则

- **成片：** 16:9横屏，约2分50秒，建筑科普讲述。
- **分工原则（2026-10-21 定）：三维只讲逻辑，品质画面交给甲方的实景和效果图。**
  - **三维负责甲方给不了的：** 麦田、造岛、楼栋转身、视线、户型两条线。三维一律用克制的白模分析风格，不追求写实。
  - **甲方素材负责品质：** 楼体、鸟瞰、窗外景、样板间。素材在 `视频/甲方提资/`。
  - **两者的衔接：** 用叠化和推镜，让三维讲到哪里，就在那里接上真实画面。
- **原则：** 成本和周期有限。**结构和节奏第一，画面细节第二。** 先用粗模型把节奏锁定，再按需补细节；不在细节上反复打磨。
- **质量底线：** 画面一直在动，没有幻灯片感；镜头之间有转场设计；字幕、配音、画面严格同步；画面干净，不穿插、不闪烁；每个镜头一眼能看懂在讲什么。

## 2. 技术路线

**选定：Remotion + Three.js。**

- **Remotion：** 用代码写视频的框架。每个镜头写成一个组件，按分镜的时间码排进时间线，逐帧渲染成 MP4，所以不会掉帧。它自带预览界面，可以拖动时间轴看每一帧，方便你审片。
- **Three.js：** 通过 Remotion 的 Three.js 插件做三维镜头：地形、造岛、楼体立起和转身、视线、户型沙盘。白模加环境光遮蔽和柔和阴影，香槟金线条，不做写实材质。
- **甲方静帧：** 在 Remotion 里做推拉、平移、局部叠光（例如窗格逐层亮灯），并和三维画面叠化衔接。
- **二维部分：** 线描肖像、上海大剧院线稿、规划线、总平面落下、花字卡、字幕，用 SVG 和 CSS 动画写在同一个工程里。

**为什么不选另外两种：**
- **HyperFrames：** 用 HTML 写视频，开源（Apache-2.0），也适合 AI 写代码。但版本还在0.8，做二维动效合适，做大量三维镜头不如 Remotion 成熟。保留为备选。
- **只用 JavaScript 自己写渲染管线：** 之前两版视频就是这样做的，自由度高，但时间线、预览、音画同步都要自己造，周期更长。

**需要你确认一件事：** Remotion 对个人和3人以内的公司免费，更大规模的公司商用需要购买公司授权。如果你们团队超过3人，或者这条片子算公司商用，请先确认授权；不方便的话，我就换用 HyperFrames，它没有这个限制。

### 户内和品质镜头的做法（2026-10-21 第二次修订）

**为什么改：** 写实材质的样图和甲方样板间实景一比，差距明显。样板间是深色木、灰色石材、黑色金属、暖光，我们的贴图既做不出这种质感，色调也对不上。豪宅片里，这种差距会直接拉低项目品质。

**怎么做：**
- **户型沙盘只讲逻辑。** 镜19–22保持白模分析风格（就是样图①那一种），两条线用香槟金。每到一个节点，叠化成该空间的样板间实景，再回到沙盘。
- **人视镜头全部用样板间实景。** 照片做推拉和视差；甲方的样板间视频到了以后，优先用视频。
- **楼体、窗外景、夜景全部用甲方效果图。** 在 Remotion 里做推镜、叠光，和三维镜头叠化衔接。
- **AI 视频生成只作补充。** 只在甲方静帧需要真实运动时（比如水面、灯光、云）做图生视频，需要甲方同意上传。不再用 AI 编造任何建筑、户型或景观。
- **取消项：** 写实材质渲染、A/C 样片对比、木地板重选（W1）。已收的材质和 HDRI 留作备用，不再追加。

**M3 关键镜头样片改为三个：**
1. **转身：** 三维转身，叠化到甲方日景鸟瞰。
2. **穿窗进屋：** 甲方楼体效果图推镜，叠化到样板间客厅。
3. **纵线：** 白模沙盘滑行，节点叠化样板间实景。

**M1 为什么最重要：** 结构和节奏是这条片子成败的关键，而且改动成本最低。在粗片阶段把节奏定死，后面精制时就不会返工。

### 画面精度提升（2026-10-21，回应模型粗片审阅）

**结论：** 模型粗片只是“把真实模型接进节奏”，用的是最基础的光和材质。成片之前还要做一轮画面精度（look-dev）。先做三个样片给你确认风格，再推到全片：
- 镜4的路网，代表线条风格；
- 镜6的引水，代表水面风格；
- 镜26的客厅，代表户型段风格。

**要做的事：**

| 问题（审阅意见） | 做法 |
| --- | --- |
| 线条有的柔和、有的生硬（第4条） | 所有线（规划线、路网、岛轮廓、户型两条线）统一成一套发光线：固定像素宽度、抗锯齿、头部带光点，加泛光后期。长风商务区的路网也用同一套 |
| 水面粗糙，内河和汾河断开（第2、5条） | 水面加深浅渐变、岸线高光、缓慢流动的波纹；内河从汾河的口子流进来，水头带光，和汾河连成一体 |
| 地面只有一块黑（第2条） | 田地加田垄纹理；暗场地面加微弱起伏和远处西山轮廓光 |
| 实景切换生硬（第8条） | 三维机位对准效果图的视角，先让灯光亮起，再按亮度渐显叠化，不再整幅淡入淡出 |
| 平台、人车看不懂（第6条） | 配音先改为“筑起一座大平台”；甲方确认人车分层后，再做平台剖面：下层车流光带，上层行人小点 |
| 馆名和光柱没呼应（第7条） | 馆名挂在各自光柱的顶端，跟着三维位置走 |
| 镜11突兀（第9、17条） | 不再贴总平面图，改用模型生成楼栋平面；从文化岛沿汾河一镜滑到瑞府 |
| 户型段（第13–16条） | 三维“剖切沙盘”加分区铺色。讲到某个区域时，镜头固定在这个区域；区域里放软装配色和低多边形小人；每个区域单独打光（下午、傍晚、夜晚）；标签带引线。不再用任何样板间照片 |
| 两条线歪歪扭扭（第14条） | 改为两条笔直的示意线，不再沿相机路线画 |
| 夏邦杰肖像（第3条） | 按事务所纪念页的官方照片描成金色线稿，替换现在的占位脸 |

**需要的新素材：** 低多边形小人（站、坐、走）和少量软装模型，许可要 CC0。交给素材 Agent，见任务书 TASK-005。

### AI 生成的使用范围（2026-10-21 用户定）

| 段落 | 做法 | 原因 |
| --- | --- | --- |
| **区域大场景**：田地、规划线、造岛、五馆、长风商务区、华润项目、沿汾河到瑞府（镜1–11c），以及尾声的城市夜景 | **用即梦把三维白模和夜景渲染提成“大片感”画面**：三维提供准确的地形、岛形、五馆位置和机位，即梦负责质感和氛围 | 区域镜头要气势、要大场景，地理关系由三维锁定，AI 只负责质感 |
| **楼栋转身与视线**（镜12–20） | 三维为主，必要时同样用即梦提质感 | 转身角度、视线方位必须精确 |
| **户型段**（镜23–33） | **不用 AI 生图**。三维功能演示：矮墙平面、分区高亮、固定机位、中性配色、中性小人，强调空间和动线，不渲染豪华感 | 项目有明确的交付标准，户型段只讲功能，避免和样板间实景、交付标准冲突 |

即梦工具：即梦创作 CLI（`dreamina`），已安装登录（2026-10-21）。每批生成前先报数量，用户同意再跑。

## 5. 我的质检清单（每次交付前都过一遍）

- **结构：** 每一段的“揭晓”都清楚；没有哪一段拖沓超过15秒没有新信息。
- **节奏：** 转身前的半秒空白、“豪宅比的，是窗外”之后的停顿都在；转场没有生硬跳切。
- **画面：** 一直在动；没有穿插、闪烁、穿帮；奶白和暗色两套色调统一；花字字体统一，位置统一。
- **同步：** 字幕和配音误差不超过0.2秒；关键动作踩在配音的关键词上，例如“转了个身”落在楼体开始转动的那一刻。
- **事实：** 所有数字、名称、口径和分镜脚本“需要核实”一节一致；示意画面都有标注。
