# 地形高度图交付说明

本文件对应 TASK-002 第4.2节。源数据只读，未下载补块，未生成网格。

在 `视频/模型/` 目录运行一条命令即可重建本组文件和校验报告。

```sh
.venv/bin/python 源文件/build_terrain.py
```

- `height.png` 为 2048×2048 的16位灰度PNG。有效编码范围1–65535，0为NoData。
- `valid_mask.png` 为同尺寸8位有效性遮罩。255有效，0无数据。采用最近邻采样，避免把无数据混入高度。
- `terrain_meta.json` 记录公共原点、UTM外框、原始外框投影边界、像元间距、编码公式和 Three.js 读取建议。
- `preview.png` 左图核对西山与汾河谷地，右图叠加城市层的汾河水面轮廓。水系地理数据范围小于地形范围，未补画范围外的河流。
- `../校验/terrain_audit.json` 为独立源PNG采样、瓦片接缝、UTM反变换与PNG编码回读检查。

输出在公共EPSG:32649米制网格上等距采样，并非把经纬度外框等距拉伸。经纬度矩形投影后是斜边形，2048输出采用其UTM包围矩形，**仅原外框之外的矩形角部为NoData，占3.819728%**。原外框内有效像元无缺失，不对瓦片外区域做边缘外推。导演建立地形时，应按遮罩跳过无效网格单元，或按元数据里的原外框投影边界裁切。

图像第一行在北侧，场景Z最小；最后一行在南侧。外框描述像元外边界，像元中心位置为 `x=x_min+(column+0.5)*dx`、`z=z_min+(row+0.5)*dz`。几何顶点在边界上时，应由场景位置求UV并采样，不能把2048个像元中心当作两端边界。像元间距X=11.260663米、Z=5.592116米，不同轴间距是正常的。源z13地面采样约15.1米，输出增密不会增加原始细节。

16位值应直接解码，避免通过浏览器8位Canvas或sRGB颜色处理丢失精度。推荐解码Uint16后，转为 `Float32(code/65535)`，装入无颜色空间的 `THREE.DataTexture(RedFormat, FloatType)`，`flipY=false`，定义北侧 `v=0`、南侧 `v=1`。`PlaneGeometry` 旋转为水平面后原有UV常为北侧 `v=1`，需反转一次V或明确重设UV，不应同时翻图。

解码绝对海拔为 `min_m+(code-1)/65534*(max_m-min_m)`。场景高度为 `sceneY=absolute_elevation_m−777.5528941834241`。基准来自大剧院公共原点处的DEM双线性采样，**只是动画对齐基准，不是实测室外地坪或建筑±0.000**。原高程服务包含混合来源，垂直基准未经独立测绘核验。城市平面图层使用既定Y偏置，河道地形存在自然高差，不把整条河道强行压平为固定水面。
